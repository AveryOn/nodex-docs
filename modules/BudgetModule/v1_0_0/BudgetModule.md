## Budget

Сущность Budget представляет собой основную единицу бюджетной записи.

### Поля

- id (uuid, pk) — идентификатор
- title (string, not null) — название
- description (string, nullable) — описание
- amount (decimal, not null) — сумма
- currency\_id (uuid, not null) — внешний ключ на валюту
- planned\_at (date, nullable) — дата планирования
- budget\_block\_id (uuid, not null) — связь с родительским блоком
- created\_at (date, not null) — дата создания
- updated\_at (date, nullable) — дата обновления
- deleted\_at (date, nullable) — дата мягкого удаления
- status\_id (uuid, not null) — связь со статусом
- scope\_id (uuid, not null) — связь с областью

Сущность описывает единицу траты. Все операции планирования выполняются через неё.

### Обязательные поля

- title
- amount

### Необязательные поля

- description
- currency\_id
- planned\_at
- budget\_block\_id
- created\_at
- updated\_at
- deleted\_at
- status\_id
- scope\_id

### Поведение

После создания запись отображается в списке бюджета.

Доступные действия:

- выполнить
- удалить

Редактируемые поля:

- tags (через BudgetTags)
- title
- amount
- description
- planned\_at
- scope\_id

### Разделение по областям

Записи группируются по scope\_id.

### Отображение

Отображаются только активные записи:

- status = active
- deleted\_at IS NULL

> Заметка: требуется определить поведение для записей с просроченным planned\_at и статусом expired.

## BudgetBlock

Сущность BudgetBlock представляет собой родительскую сущность для Budget.

Она используется для логического объединения бюджетных записей в более крупные тематические группы. Это позволяет структурировать бюджет при росте количества записей. Например, отдельные блоки могут использоваться для бюджета дома и бюджета предстоящего отпуска.

В рамках MVP количество блоков не ограничено. В будущем возможно введение лимитов для free-версии приложения.

### Назначение

- логическое разделение записей Budget
- повышение читаемости
- упрощение навигации по бюджету
- группировка записей по крупным темам

### Отображение

BudgetBlock отображается как отдельный визуальный блок.

Внутри блока отображаются:

- title
- amount
- агрегированные счетчики записей Budget по статусам

Пример агрегированных счетчиков:

- active — 10 (budgets)
- expired — 3 (budgets)
- completed — 6 (budgets)

Для каждого счетчика используется семантически соответствующий цвет.

### Поведение

На отдельной странице отображается список всех блоков бюджета.

Каждый блок является кликабельным. При переходе в блок открывается страница Budget со всеми записями, относящимися к выбранному BudgetBlock. Внутри страницы записи отображаются в таблице и дополнительно разделяются по scope, как описано в сущности Budget.

## BudgetScope

Сущность BudgetScope определяет область, к которой привязана запись Budget.

Связь реализуется через поле budget.scope\_id.

### Поведение по умолчанию

При создании Budget, если scope не указан, используется базовая область со значением `main`.

В этом случае:

- выбирается существующая запись BudgetScope с name = `main`
- её id записывается в budget.scope\_id

### Создание новой области

Если при создании Budget указан новый scope, который отсутствует в системе:

- создаётся новая запись в BudgetScope
- генерируется новый id
- устанавливается name (например: `1 week`)
- этот id используется в budget.scope\_id

### Назначение

- логическое разделение записей Budget внутри блока
- гибкая группировка (например: по неделям, периодам, категориям)
- улучшение читаемости и навигации

### Примечание

Scope не является обязательным полем на уровне ввода, но всегда присутствует на уровне данных (через fallback на `main`).

## BudgetScopeOrder

Сущность BudgetScopeOrder определяет порядок отображения групп записей Budget, агрегированных по scope.

### Назначение

- управление порядком отображения областей (scope)
- улучшение UX при работе с большим количеством записей
- устранение неочевидного порядка (например: `2 week` после `3 week`)

### Проблема

При создании записей Budget и последующем назначении scope порядок областей формируется неявно и может выглядеть хаотично.

### Решение

Пользователь может управлять порядком областей вручную.

На уровне интерфейса:

- области (scope) отображаются как группы записей
- пользователь может изменять их порядок (например: перемещение вверх/вниз)

На уровне данных:

- порядок фиксируется в BudgetScopeOrder

### Поведение

- пользователь изменяет порядок областей
- система сохраняет новый порядок
- порядок применяется при отображении Budget

Это обеспечивает предсказуемость и контроль над структурой данных.

## Tag

Сущность Tag является общей (shared) сущностью системы и может использоваться в различных модулях.

Связь с другими сущностями реализуется через промежуточные таблицы вида `{entity}_tag`.

### Поля

- id (uuid, pk) — идентификатор
- name (string, not null) — название тега
- color (string, not null) — цвет (hex)

### Использование в BudgetModule

В контексте BudgetModule теги связываются с сущностью Budget через промежуточную таблицу BudgetTag (`budget_tag`).

Тип связи:

- many-to-many (один Budget может иметь несколько тегов)

### Назначение

- логическое разделение записей Budget
- упрощение навигации
- фильтрация и поиск
- обозначение принадлежности записей к определённым категориям или контекстам

## Currency

Сущность Currency также является shared-сущностью системы, но в основном используется в рамках BudgetModule.

Она представляет собой справочник валют, который используется для связи с записями Budget и позволяет определить, в какой валюте указана конкретная сумма.

### Назначение

- хранение списка доступных валют
- связь с записями Budget
- отображение валюты для каждой бюджетной записи
- использование в будущих сценариях конвертации и суммирования

### Использование

Каждая запись Budget содержит ссылку на Currency через поле `currency_id`.

Это позволяет явно фиксировать валюту каждой суммы и корректно отображать её в интерфейсе.

### Будущее расширение

На основе сущности Currency планируется реализовать калькулятор валют для Budget.

Цель — дать возможность суммировать записи Budget независимо от того, в каких валютах они созданы.

Пример:

- 50 USD
- 34 GEL

При выборе этих записей система сможет показать итоговую сумму в выбранной валюте, например:

- ≈ 62 USD

Валюта итогового суммирования также должна выбираться пользователем через селектор.

По умолчанию используется валюта USD ($).

Подробная логика конвертации и суммирования будет описана отдельно.
