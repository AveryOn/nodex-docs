# Task Manager — полный собранный контекст

## 1. Что это за проект

**Task Manager** — твой личный проект.

Изначально он описывался как:

> личный task manager + budget manager.

Позже контекст расширился. Сейчас по смыслу это уже не просто “таск-менеджер”, а личная система фиксации, напоминаний, бюджета, заметок, бытовых операций, дневника и расходуемых ресурсов.

Проект нужен:

* для личного использования;
* как архитектурная практика;
* как потенциальный portfolio case;
* как система, которая помогает не забывать важные вещи;
* как единое место для задач, заметок, бюджета, напоминаний и личных записей.

Текущий фокус в прошлых обсуждениях был на `BudgetModule`.

Проект находится в ранней стадии. Формальной документации почти нет. `v1.0` только начал оформляться.

---

# 2. Главная проблема проекта

Зафиксированная проблема:

> ты можешь начать реализацию раньше, чем зафиксирована доменная модель.

Это риск, потому что без доменной фиксации можно неправильно определить сущности, связи, границы модулей и поведение системы.

Поэтому перед реализацией нужен промежуточный слой:

```txt
Domain Specification
```

То есть не сразу код, таблицы, DTO и API, а сначала:

* scope;
* словарь терминов;
* сущности;
* инварианты;
* поведение;
* use cases;
* decision rules;
* boundaries;
* open questions.

# 19. Расчёт расходуемого ресурса

Для препарата нужно считать:

```txt
остаток после приёма
```

В двух измерениях:

```txt
1. сколько мг осталось
2. сколько элементов упаковки осталось
```

Пример логики:

```txt
totalPackageItems = 30 tablets
dosagePerItem = 15mg
intakeDose = 15mg

after intake:
remainingItems -= 1
remainingMg -= 15
```

Но если дозировка приёма может быть меньше таблетки, например половина таблетки, тогда нужна дробная логика:

```txt
intakeDose = 7.5mg
dosagePerItem = 15mg

consumedItems = 0.5
remainingItems -= 0.5
remainingMg -= 7.5
```

Это важный доменный момент.

# 20. Связь счётчиков с reminders/checklists

Ты хочешь, чтобы счётчики можно было привязывать к реальным сущностям.

Например, есть ежедневное напоминание со списком:

```txt
Миртазапин 15мг
Ламотриджин 50мг
Пароксетин 10мг
Кветиапин 25мг
```

Для каждой строки checklist привязан свой counter.

Когда ты зачеркиваешь пункт, например:

```txt
Миртазапин 15мг
```

система должна:

```txt
1. отметить пункт выполненным
2. найти связанный счётчик
3. списать нужное количество
4. пересчитать остаток
5. проверить alert threshold
6. если остаток <= threshold, создать alert/notification
```

Это важная связка:

```txt
ReminderChecklistItem -> ConsumableCounter -> DecrementOperation -> Alert
```

# 28. Главный вывод по текущему состоянию

Task Manager нельзя сейчас считать просто task manager.

По текущему контексту это:

```txt
Personal Life Management System
```

или точнее:

```txt
Personal Memory, Reminder, Budget and Resource Tracking System
```

Но рабочее название может оставаться `Task Manager`.

Фактическое ядро:

```txt
личная внешняя память + напоминания + финансовый учёт + связанные сущности
```
